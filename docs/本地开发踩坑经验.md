# 本地开发踩坑经验

这份记录来自原生团队版 v1 的本地开发、返修和 Docker 验收。面向后续二开，按常见故障提供定位入口和复验方法。安装、备份与人工验收的完整命令见 [原生团队版 Docker 验收](guides/native-teams.md)。

## 1. 确认浏览器访问的是正在编辑的版本

同一台机器同时运行原审查实例和团队版时，端口、Compose 项目名、源码挂载和数据卷都要核对。连接到正确端口但挂载了另一工作树，容易把旧前端的问题当成新代码的回归。

- 从已确认的 Git 基线建立独立工作树。修改前用 `git worktree list` 和 `git status --short --branch` 核对当前目录与分支。团队 Compose 将源码只读挂载到 `/a0`，并且按项目名分配 `usr` 和 `tmp` 卷。每个用户卷由一个 WebUI 进程使用。
- Git 工作树的 `.git` 指向公共 Git 目录。Compose 需要能在容器内以同一路径读取该目录，版本检查才能与实际源码对应。启动后同时核对 `docker compose ps`、实际挂载和浏览器端口。 [团队 Compose](../docker/team/compose.yaml)
- 源码已变但浏览器还显示旧控件时，先核对容器加载的源码。验收实例空闲后重启对应 WebUI，再用新的浏览器上下文复验。启动时下发的 WebUI 资产包和 Service Worker 缓存会影响只刷新旧标签页的结果。 [WebUI 加载约定](../webui/AGENTS.md)

在团队工作树执行以下检查。端口取自当前 QA 的实际配置。

```bash
export A0_TEAM_SOURCE="$(git rev-parse --show-toplevel)"
export A0_TEAM_GIT_COMMON="$(git rev-parse --path-format=absolute --git-common-dir)"
export A0_TEAM_PORT=5081
docker compose -p agent-zero-native-team-qa -f docker/team/compose.yaml config --quiet
docker compose -p agent-zero-native-team-qa -f docker/team/compose.yaml ps
curl --noproxy '*' --fail --silent "http://127.0.0.1:${A0_TEAM_PORT}/api/health"
```

## 2. 沿用原生入口，逐条验证权限

本次交付的最短路径是子账号在原生页面登录，选择已分配的项目，发送首条消息并在刷新后打开历史。二开优先沿用这条路径里的登录、Projects、输入区、聊天树和扩展点。新增原生按钮时，同时检查成员的 WebUI 扩展清单和对应服务端操作的项目范围。成员首页的四个快捷入口复用了原生卡片，Files 在欢迎页没有活动项目时先打开项目选择器。 [页面扩展指南](developer/extensions.md) · [团队权限入口](../helpers/team_access.py)

| 需要排查的现象 | 定位和复验 |
| --- | --- |
| HTTP 项目列表正确，已连接的页面仍残留撤权项目 | 对照 HTTP 轮询与 WebSocket 首次状态、增量推送和重连。成员快照携带当前授权项目名，包括空项目。撤权后检查文件夹和已打开会话同步退出。 |
| 同名目录重建后出现旧项目数据或授权 | 核对项目目录内的持久标识与权限库绑定。已有明确原生项目归属的历史沿用原生会话，归属不明确的历史保留原状。复验旧会话标题、历史和作者。 |
| 子账号左栏混排不同项目的聊天 | 用原生文件夹视图，按照已分配的项目组织原生聊天行。用一个双项目账号和一个单项目账号检查空文件夹、展开、刷新和实时撤权。 |
| 页面能打开资料，审计查看范围有误 | 分别验证项目资料与聊天权限、审计事件可见性、审计正文授权。角色分配、账号失效和 CSRF 在相关入口一起复验。 |

## 3. 把空白草稿、共享历史和运行轮次分开

- **点 New Chat 就多了一条历史。** 欢迎页当前选中的项目和空白草稿保存在前端。首条有效发送才提交原生会话。复验时在空白页连续点击 New Chat，同时比对原生 `chat.json` 和 SQLite 轮次数量。随后发送一条消息并核对落盘。
- **续聊之后管理员看到临时标题或空历史。** 从原生上下文、持久化和两个角色的快照逐段核对同一个会话 ID。已分配项目的会话默认共享，列表使用原生标题，双方读取同一原生日志。
- **多标签页快速提交让同一会话启动两次。** 运行占用由服务端原子登记。并行试验分成同会话与同项目不同会话两组。同会话冲突返回 `409`，未被接受的输入留在草稿。重试应保留原 `message_id`，核对原 `run_id` 和模型实际调用次数。进程中断后的复验同时检查运行状态和已落盘的会话历史。

## 4. 复验多人写入和项目内工具

- **配置或文件被另一个页面覆盖。** 表单和文件写入应携带读入时的修订。收到 `409` 后保留编辑草稿，展示当前版本，再由用户复审后提交。用两个成员页面和一次 Agent 写入交叉验证，最后重新读取真正落盘的文件。
- **上传两个子目录里的同名同大小附件只剩一个。** 项目文件夹上传需要保留相对路径。用不同子目录的同名文本复验两个附件都被发送，另一成员能从共享历史读到正确路径与内容。
- **在首页或侧栏能开工具，以项目身份执行时范围偏了。** 对照 Files、Editor、Memory、Scheduled Tasks 各自的项目入口和服务端作用域。用原生工具在一个授权项目读写，再用另一个项目或被撤权的账号验证访问结果。任务手动运行用发起者身份，到期运行复查创建者当前授权。

## 5. 浏览器和桌面要验证真正的图形操作

- **Browser 能开项目 HTML，公网网站加载失败。** 先分别验证项目文件和公开网页。在使用返回合成地址的本机代理时，检查选用的 Compose 代理配置、DNS 解析结果和页面加载。项目 Browser 的代理核验公网目标后再连接。用地址栏导航和实际页面内容作为证据。 [本机代理配置](guides/native-teams.md#使用本机-http-代理的网络)
- **Desktop 能打开窗口，项目文件还是旧版本。** 桌面应用先保存会话内暂存文件，再在 Agent Zero 点击 **Save to Project**，以版本检查写回项目。用另一浏览器会话重读共享文档确认。图形界面启动异常时核对宿主 Landlock ABI、项目会话和 Xpra 日志。本次图形隔离要求 Linux Landlock ABI 6 或更高。 [项目图形会话](../helpers/team_surfaces.py) · [本地图形隔离](../helpers/team_surface_sandbox.py)

## 6. 用对 Python 环境，分开记录两类结果

Docker 有两个 Python 环境。WebUI、API、插件钩子和 pytest 使用框架环境 `/opt/venv-a0`，Agent 的终端任务使用 `/opt/venv`。运行镜像缺 pytest 时，将 [开发测试依赖](../requirements.dev.txt) 装入独立 QA 临时目录，在框架环境运行测试。离线执行时准备测试使用的 tokenizer 缓存。扩展点回归会在 `plugins/` 下创建临时探针，应用只读挂载时用可写的临时源码副本执行该组。 [Docker 运行约定](../docker/AGENTS.md) · [测试约定](../tests/AGENTS.md)

下面是二开后可先执行的回归子集。在已有对应依赖的框架环境与源码根目录运行。

```bash
python -m pytest -q tests/test_chat_create.py tests/test_chat_attachments.py \
  tests/test_team_store.py tests/test_team_runs.py tests/test_snapshot_schema_v1.py \
  tests/test_snapshot_parity.py tests/test_team_browser_proxy.py
node plugins/_sidebar_folders/tests/test_frontend.mjs
node --test plugins/_sidebar_folders/tests/test_search_frontend.mjs \
  tests/test_welcome_sections.mjs tests/test_welcome_layout.mjs tests/test_file_browser_views.mjs
```

- **真实模型验收**从原生页面登录、选项目并首发。核对实际回复、刷新后的历史和项目归属。DOM 可见与 HTTP 接受只是发送过程中的检查点。
- **可控模型复验**用于稳定复现并发、队列、停止和容器中断。记录请求 ID、运行 ID、模型调用次数和持久状态。用独立浏览器上下文区分成员，用同一账号的两个标签页验证会话竞争。
- **升级与回滚**将镜像摘要、实际源码版本和预升级用户卷一起登记。将备份恢复到新的 Compose 用户卷，验证原生登录、历史、授权、文件内容和重启持久化。模型凭据、签收账号、数据库、私有对话和原始验收截图留在本地受限存储。 [备份、升级与回滚](guides/native-teams.md#备份升级与回滚)
