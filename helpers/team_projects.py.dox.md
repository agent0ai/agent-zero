# Native team project settings and files

- `project_lock()` checks the stable native binding and serializes managed changes by project in the single team framework process.
- Ordinary settings edit only the public native header fields. Compare the header digest before writing. Use the native header writer and refresh project metadata for its chats.
- Workspace, instructions and knowledge are three roots within the same native project. Member file paths are relative to one root. Open directories without following links. Skip hidden entries, symbolic links, nonregular files and multiply linked files.
- Team prompt instructions use the same descriptor-pinned file reader and a bounded text budget.
- Text edits compare the current SHA-256 under the project lock. New files and uploads require an absent target. Writes publish through the pinned directory descriptor using the native bounded file transfer helper. Deletion requires an existing matching revision.
- Team changes recorded by `activity()` include the actor and project. File names, contents, and settings stay in native storage.
- Verify two members loading and saving the same files and project header, stale revisions, cross-project authorization and rejected links.
- Files, Editor and chat attachments use pinned workspace descriptors. Chat attachments have a run-specific directory. File moves use a no-overwrite rename. Empty folders can be removed after version verification.
